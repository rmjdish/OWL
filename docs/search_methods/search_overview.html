About the Searches

OWL gives you five different ways to find NSHD variables, each suited to a different kind of question. This page explains what each search does, how its filtering and results work under the hood, and when to reach for it.

Every NSHD variable lives in a single underlying data dictionary, but the right entry point into that dictionary depends on what you already know and what you're trying to do. Do you have a rough topic in mind but no exact variable name? Do you want to know what other researchers have used most often? Are you trying to pin down every variable collected in a particular sweep? Or do you need a guaranteed like-for-like measure across time? Each search below answers one of those questions well — the sections that follow go through them one at a time, then close with a comparison to help you pick.

Which search do I need?

"I want to browse or keyword-search everything" Use Search Data Dictionary — the full dictionary, filterable by category and free-text keyword.
"I know the general subject but not the variable" Use Browse by Category — drill down through topics and subtopics in the sidebar.
"What do other researchers usually use?" Use View Popular Variables — ranked by how often each variable has been added to a project basket.
"I need a guaranteed like-for-like measure across sweeps" Use Longitudinal Search — only variables with identical question text and coding across two or more sweeps, with trajectory charts built in.
"I need everything collected in a given sweep" Use Search by Year — filter by collection year, including rolling collection windows and named studies.

Search Data Dictionary

This is the broadest entry point into OWL: every variable in the NSHD data dictionary, in one searchable, filterable table. It's the right starting point whenever you don't yet know exactly which variable, category, or sweep you need.

How it works: the full dictionary loads into the page and is organised using the same hierarchical category structure used throughout OWL — top-level topics with nested subtopics. A filter bar above the table lets you narrow the results to a category before you start typing, and the global search box matches keywords against variable names, labels, and other metadata fields simultaneously, so a search term doesn't need to match the exact field you're thinking of.

Filtering and pagination: filters and the search box combine — narrowing by category first, then searching within it, is the fastest way to cut down a large result set. The page size selector lets you show 15, 30, 50, or 100 rows at once, and pagination controls appear both above and below the table so you don't have to scroll back to the top to move between pages. A single Reset Filters button clears the category filter, search box, and sort order back to defaults.

Advantages:

  • Covers every variable in the dictionary — nothing is excluded the way it can be in the more specialised searches
  • Keyword search covers multiple metadata fields at once, so partial or approximate terms still surface the right rows
  • Combining category filters with keyword search narrows very large result sets quickly
  • Results can be added to the basket in bulk with Add All to Basket, or individually per row
  • Results and the full dictionary can both be downloaded — results as a CSV of the current filtered view, or the complete dictionary as an Excel workbook

Browse by Category

Where Search Data Dictionary asks you to type a keyword, Browse by Category asks you to navigate — it's built for exploring the structure of the dictionary itself, rather than searching within it.

How it works: variables are organised into a hierarchical category structure — demographics, lifestyle, clinical outcomes, biological markers, and similar top-level topics, each with its own nested subtopics. Every topic and subtopic has its own dedicated page, and the sidebar menu provides a collapsible tree for moving between them without long in-page scrolling.

Navigation behaviour: top-level topics appear as main sidebar headings, with subtopics nesting automatically beneath their parent. Sections can be expanded or collapsed individually so you can focus on one branch of the hierarchy at a time. The sidebar always highlights the current page, and a breadcrumb-style structure keeps track of your position within the hierarchy, so it's easy to move back up a level or sideways to a related subtopic.

Advantages:

  • Best suited to exploratory browsing when you know the general subject area but not the specific variable or field name
  • Reveals related variables you might not have thought to search for, since neighbouring subtopics sit right next to each other in the tree
  • Makes the overall structure of the dictionary visible at a glance, which helps when scoping a new project
  • Consistent sidebar navigation means you're never more than a click or two from a related topic

View Popular Variables

This search answers a different question from the others: not "what variables exist," but "what have other researchers actually used." It's a ranked list of the variables most frequently added to project baskets.

How it works: the page tracks how many times each variable has been added to a basket across different projects between January 2021 and December 2025, and only shows variables that were added more than 15 times in that window — so the list surfaces genuinely well-used measures rather than one-off additions. Each row shows the NSHD variable name, its Showcase Field ID, the variable label, and the running count.

Filtering and sorting: the table columns — name, Field ID, label, and count — are all independently sortable by clicking their headers, so you can order the list by popularity or browse it alphabetically by name or label instead. The global search box filters across these same fields, and results can be paginated at 15, 30, 50, or 100 rows per page, matching the other search pages.

Advantages:

  • Useful for quickly identifying well-established, widely-used measures when you're not sure which variable within a construct is the standard choice
  • The 15-use threshold filters out rarely-used variables automatically, so the list stays focused on genuinely popular measures
  • Sortable by count to see the very most-used variables first, or by name/label for quick lookup
  • Same bulk basket and CSV/Excel download options as the other searches, so a shortlist of popular variables can be exported or added to a project in one step

Longitudinal Search

Longitudinal Search is the most specialised of the five: it's dedicated entirely to finding variables that were collected with identical question text and coding across two or more sweeps, so that values can be compared directly across the lifespan.

How it works: every variable is grouped by its Showcase Field ID — the same identifier the NSHD Showcase uses to link variables that share identical question text and response coding. Only Field IDs appearing in two or more sweeps are included, since single-sweep variables have nothing to trace longitudinally. Grouping is deliberately strict: if a question was reworded, response categories changed, or the unit of measurement shifted between sweeps, the NSHD Showcase treats those as separate fields, and so does this search — which guarantees that anything shown as a trajectory is a genuine like-for-like comparison.

Charts and detail: clicking View on any Field ID reveals a trajectory chart. For continuous measures (height, weight, blood pressure) this is a line chart of the mean at each sweep with a shaded band for the observed minimum and maximum. For categorical measures (self-rated health, yes/no items) it's a stacked bar per sweep showing the share of respondents in each response category. A detail table beneath the chart gives the same information numerically, one row per sweep.

Filtering: the search box matches the variable label, Field ID, and any individual variable name within a group, so searching a familiar variable name (e.g. ht82) surfaces the whole longitudinal group it belongs to. A minimum sweep count filter (2+, 3+, 5+, 7+, or 10+) narrows to measures with real longitudinal depth, and a topic filter restricts to a single subject area.

Advantages:

  • The only search that guarantees strict like-for-like comparability across sweeps — essential before using a measure in a longitudinal analysis
  • Built-in trajectory charts and detail tables save the work of manually assembling a variable's history across sweeps
  • Sweep-count filtering lets you find measures with particularly long follow-up (up to 28 sweeps, spanning 1946–2025)
  • Basket controls work at both the individual-sweep and whole-group level, including bulk add/remove for every sweep in a Field ID at once
If a variable doesn't appear here but you believe it should be comparable across sweeps despite some change in wording or coding, check its individual metadata page for the more flexible Linked & Longitudinal section.

Search by Year

Search by Year flips the usual question around: instead of starting from a variable or topic, you start from a point in time and ask what data was collected then.

How it works: a row of year pills across the top of the page represents every NSHD sweep. Clicking a pill filters the table to variables collected in that year; clicking multiple pills filters to variables collected in any of the selected years. Clicking an already-active pill deselects it, and an "All" option clears the selection entirely. Because some variables were collected in a single sweep and others across a rolling collection window rather than a fixed year, both types are shown and clearly distinguished. Named sub-studies that ran within the wider NSHD — Insight46, MyoFit, Covid, and Women's Health — are highlighted in colour in the pill bar and explained in an accompanying legend, so you can spot which results come from a sub-study at a glance.

Filtering: beneath the year pills, a set of topic filters (covering five levels of the category hierarchy) let you narrow by subject in addition to year. The two filters interact live — year pills that would return no results for your current topic or search term dim automatically, so you can see at a glance which years actually have relevant data before you click. The global search box, page size selector, and Reset Filters button work the same way as on Search Data Dictionary.

Advantages:

  • The fastest way to answer "what was collected in sweep X" without manually cross-checking dates against every variable's metadata
  • Distinguishes single-sweep collection from rolling collection windows, so you don't mistake one for the other
  • Colour-coded highlighting for named sub-studies (Insight46, MyoFit, Covid, Women's Health) makes it easy to isolate their variables specifically
  • Live-dimming pills combined with topic filters mean you can narrow by both year and subject at the same time and immediately see which combinations have data
  • Same bulk basket, CSV export, and Excel download options as the other searches

Features shared across all searches

Regardless of which search you use, a few pieces of behaviour stay consistent across all five, so switching between them doesn't mean learning a new interface each time:

  • Global search box: present on every search page, matching keywords against the relevant metadata fields for that view.
  • Page size and pagination: every table can be shown at 15, 30, 50, or 100 rows per page, with pagination controls above and below the table.
  • Basket controls: variables can be added individually or in bulk with an Add All to Basket button on every search page; Longitudinal Search additionally supports whole-group add/remove.
  • Downloads: a Download Results (CSV) button exports the current filtered view, and a Download Data Dictionary link provides the complete NSHD data dictionary as an Excel workbook.
  • Reset controls: where filters exist beyond the search box (category, topic, year, sweep count), a Reset Filters button clears everything back to defaults in one click.
