Basket Management

How to add, remove, upload, and export variables using the basket across the OWL.

Every results table across the OWL — Search Data Dictionary, Browse by Category, and Popular Variables — uses the same basket controls, so once you've learned them on one page, they work identically everywhere else. This page walks through each control in detail: adding variables one at a time, the Add All button and its different states, using pagination to add larger numbers of variables in fewer clicks, reviewing or exporting what you've collected, restoring or bulk-adding to a basket by uploading a file, and the maximum size a single basket submission should be.

Adding a single variable

Every row in a results table has a checkbox in the leftmost Add variable column. Ticking it adds that variable to your basket immediately — there's no separate confirmation step or save button to click afterward.

  • Instant feedback — the checkbox stays ticked once a variable is added, so you can see at a glance which rows on the current page are already in your basket.
  • Untick to remove — clicking a ticked checkbox removes that variable from the basket again, the same way it was added.
  • Header counter — the basket icon in the site header updates its running total the moment you tick or untick a row, so you don't need to open the basket page to confirm something was added.

This is the right approach when you're working through a short, specific list of variables you already know you want, rather than adding everything a search or category returns.

Longitudinal Search adds variables a little differently, since each row there represents a whole Field ID rather than a single variable. Clicking View on a row expands a detail panel where you can add every sweep to your basket in one click, or tick individual sweeps within that panel — there's no plain row checkbox to use directly, because the choice of which sweep(s) to add happens inside the expanded view instead.

The "Add All to Basket" button

Above every results table sits an Add All to Basket button, which adds every variable currently visible on the page in a single click rather than ticking each row individually. The button changes appearance and label depending on the state of the table:

Add all visible variables — teal, the default state. None, or only some, of the variables currently visible are in your basket yet.
Remove all visible variables — red, once every variable currently visible has already been added to your basket.
No visible variables to add — black, disabled. Your search or filters have returned zero matching rows, so there's nothing to add.

This toggle behaviour means the same button always reflects the current state of the table — you never need to check the basket separately to know whether the button will add or remove variables.

Using pagination to add more at once

The Add All to Basket button only acts on the variables currently visible on the page — not your entire result set. If a search returns 200 variables but your page size is set to 15, clicking Add All adds only those 15.

To add a larger number of variables in fewer clicks, increase the page size before clicking Add All. The page size control sits above the results table and offers options of 15, 30, 50, and 100 rows per page. Setting it to 100 and clicking Add All adds up to 100 variables in a single click.

For result sets larger than 100, you can repeat the process page by page — advance to the next page and click Add All again — until you've worked through the full set. The basket accumulates everything you add across pages, so there's no risk of losing earlier additions when you move to the next page.

Keep the 500-variable basket limit in mind when using Add All with large page sizes — see the Maximum basket size section below if you're working with a large result set.

Reviewing and exporting your basket

Once you've added variables — individually, in bulk, or a mix of both — the basket page is where you manage the full list. From there you can review every variable you've collected, remove anything you no longer need, and double-check labels and sweep coverage at a glance.

Downloading your basket doesn't just export your selection — it builds you a fully completed copy of the data dictionary as an Excel (.xlsx) file. Every variable in your basket is marked Y in the Request variable column, with any Role or Researcher's Notes you've added carried across too, ready to use directly in a data access request. You'll be prompted to choose where to save the file, with a sensible filename already filled in. See The Data Dictionary for what every column in the file means.

The basket persists as you move between pages and tools, so a variable added from a category browse will sit alongside one added from a keyword search — there's no need to finish in one tool before switching to another.

Uploading a basket

Your basket is stored locally in your browser — nothing is saved to a server, and no account or login is required to use OWL. That's convenient, but it also means your basket only exists on the device and browser you built it in.

Because the basket lives in your browser's local storage, it can be lost if you clear your browsing data or cookies, switch to a different browser or computer, or use a private/incognito window. If it isn't downloaded, that work is gone for good — there's no way to recover it afterward.

The safest habit is to download your basket regularly as you build it, rather than only at the very end. If something happens to your browser's storage, you can simply upload that same file back in and carry on exactly where you left off — nothing needs to be re-searched or re-added by hand.

What you can upload

The Upload dictionary button sits on the basket page, next to Clear Basket and >Download pre-filled dictionary. Clicking it opens a panel and prompts you for a file.

What you upload is always the same thing — a copy of the Data Dictionary, with variables marked Y in the Request variable column — it just doesn't matter how that Y got there:

  • Completed on OWL — build a basket on the site as normal, then click Download Basket. The Y marks are filled in for you automatically.
  • Completed manually — if you or a colleague already has a copy of the Data Dictionary and marks Y directly against variables of interest offline, that same file uploads just as easily, without needing to search for or add each variable individually on the site first.

Checks made on the file

Before anything is added, the file is checked over and any issues are reported clearly rather than added or dropped silently:

Missing variable name — rows marked Y with no NSHD Variable Name are skipped and listed by row number, since there's nothing to add without a name.
Invalid Request variable value — anything other than blank or exactly Y in that column (a lowercase y, N, or a stray note, for example) is skipped, and listed together with the variable name and the value that was found, so you can go back and fix the source file.
Duplicate variable names — if the same variable name appears more than once marked Y, only the first occurrence is kept and the rest are listed.
Over 500 variables — a heads-up if adding the file would take your basket over the 500-variable limit. This doesn't block the upload on OWL, since OWL itself has no basket-size limit — it's a reminder that the basket will need splitting before it can be uploaded to Condor. See Maximum basket size below.

Each of these appears only when relevant, and starts collapsed with a small "click for details" note next to it — click to expand and see the full list of affected rows or variable names, or leave it collapsed if you just want the headline count.

Reviewing before anything is added

Once the file has been checked, you'll see a summary line — highlighted so it stands out — showing how many variables were found, how many are new, and how many are already in your basket. Below that is a full table listing every variable that will be added, with each row marked either New or Already in basket, styled the same way as the main basket table so it's easy to read.

Nothing is added to your basket at this point. You need to click Confirm & Add to Basket to go ahead, or Cancel to close the panel without changing anything. This means you can safely upload a file just to check what's in it, and back out if it isn't the one you meant to use.

Uploading never overwrites your existing basket. Variables already present are left as they are and simply marked Already in basket in the preview — only genuinely new variables from the file are added once you confirm.

Maximum basket size: 500 variables

Baskets submitted for a project or data request should contain no more than 500 variables. This is a hard limit for any single basket submission.

If your project needs more than 500 variables, you have two options:

  • Use multiple baskets from the start — create separate baskets as you go, each kept under 500 variables, and submit them individually for the same project.
  • Build one larger basket, then split it — if it's easier to work from a single list while searching and browsing, you can build a basket beyond 500 variables and split it manually afterward into smaller baskets, each under the limit, before submitting.

Either approach is fine — the limit applies to each individual basket submission, not to how many variables you can work with across a project overall.
