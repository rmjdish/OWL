The Data Dictionary

What the data dictionary contains, how OWL helps you complete it, and how to download your version.

The data dictionary is the spreadsheet listing every variable available through OWL, along with its metadata — this is the file NSHD uses to process a formal data request. Completing it, by marking which variables you want, is a required step before submitting an application.

One of OWL's purposes is to make that step easier. Search or browse for variables, add the ones you want to your basket, and OWL can fill in most of the dictionary for you automatically. Everything on this page also works without using OWL at all — the same spreadsheet can be completed entirely by hand, and the two approaches can be mixed freely.

Two ways to complete it

Complete it on OWL

Search or browse for the variables you need and add them to your basket. When you download your basket, OWL builds a full copy of the data dictionary for you — every variable in your basket is automatically marked, along with any Role or Researcher's Notes you've added.

How basket management works →

Complete it manually

Download a blank copy of the data dictionary and work through it offline — no OWL basket required. This is also the way to finish off a partially-completed dictionary: do what you can on OWL, download it, then fill in the rest by hand in the same file.

Useful if you already know exactly which variables you want, or are working from a list someone else prepared.

Column reference

Every column in the data dictionary, grouped and coloured to match the spreadsheet itself. The last three columns are added by OWL and aren't part of the original file.

ColumnWhat it means
NSHD Library FileAn internal reference that links a variable to a specific dataset (library file).
TopicThe parent classification category this variable falls under in hierarchical category structure, e.g. Clinical data.
Subtopic 1The first-level subcategory beneath Topic.
Subtopic 2The second-level subcategory, where the hierarchy goes deeper.
Subtopic 3The third-level subcategory, where used.
Subtopic 4The fourth and most specific subcategory level, where used.
NSHD Variable NameThe short coded identifier used in the dataset and when requesting the data, e.g. bmi15x.
Showcase Field IDNumeric identifier linking to this variable's entry on the NSHD Showcase, where identically-coded variables are grouped together across sweeps.
UKLLC Dataset Name(s)The dataset(s) this variable is available within the UK Longitudinal Linkage Collaboration (UKLLC) platform, where applicable.
Variable LabelPlain-English description of what the variable measures.
Value labelsThe coded values and their meanings for categorical variables, or missing-data codes for continuous variables.
UnitsUnit of measurement for continuous variables, e.g. cm, kg. Shows "Not applicable" for categorical variables.
FormThe data collection instrument the variable came from — e.g. postal questionnaire, nurse schedule, home visit.
Question NumberThe specific question number within that form.
Year of collectionThe year or year range data was collected, corresponding to a specific study sweep.
Is variable derived?Whether the variable was directly measured or recorded (No), or calculated from one or more other variables (Yes).
Is variable sensitive?Whether the variable is sensitive, so researchers must take extra care when using the variables in their project.
Reason variable is sensitiveWhere applicable, the reason why this variable is restricted.
NotesFree-text contextual notes — measurement conditions, known caveats, or recoding details specific to the variable.
Request variableMarked Y if you've added this variable to your basket on OWL — this is the field NSHD uses to identify which variables you're requesting. Left blank for every other row.
Variable RoleOptional. A dropdown for your own use — tag a variable as Exposure, Outcome, Covariate, or Other, however it fits your analysis plan.
Researcher's NotesOptional. Free text for your own working notes about the variable — not read or required by NSHD.

Variable Role and Researcher's Notes are optional

These two columns exist purely to help you organise your own thinking while you work through the dictionary — for example, keeping track of which variables are your primary exposure versus a covariate, or jotting down why you picked a particular variable so you remember later.

Neither is required by NSHD, and neither is read as part of your data request. Leave them blank if you don't find them useful — only the Request variable column needs to be filled in (with Y) for a variable to be included in your application.
