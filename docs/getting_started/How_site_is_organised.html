How the site is organised

Three core mechanisms make up the OWL: search-first tools, explore documentation, and the variable basket.

The OWL is built around three core mechanisms. Search-first tools work by keyword, for when you already have something to look for. Explore documentation lets you explore by subject or by sweep without a specific target in mind. The basket ties both together, letting you collect variables as you find them, from either approach, into a single exportable list.

Search-first tools

Five tools return results as a table you can filter, sort, and export:

  • Search Data Dictionary — search across every variable in the dataset by keyword, then narrow further using the filter bar at the top, which lets you drill into specific topics and subtopics without leaving the results view.
  • Browse by Category — open any category or subcategory page (like a specific questionnaire instrument) to see just the variables within it, in a focused table rather than the full dataset.
  • Popular Variables — see which variables have been added to baskets most often by other researchers between January 2021 and December 2025, limited to variables used more than 15 times, as a shortcut to commonly-used measures.
  • Longitudinal Search — see every variable collected with identical question text and coding across two or more sweeps, grouped by Field ID rather than listed one row per variable, so you can view a measure's full sweep-by-sweep trajectory before deciding which sweeps to use.
  • Search by Year — start from a point in time rather than a variable or topic: a row of pills across the top represents every NSHD sweep, and clicking one or more filters results down to variables collected in those years, with topic filters alongside that dim automatically for any year with no matching results.

The first three share an identical toolbar and table layout, so once you know one, you know them all:

  • Search box — filters the current table live as you type.
  • Page size — choose how many rows to show at once (15, 30, 50, or 100).
  • Sortable columns — click any column header to sort the table by that field.
  • Add all to basket — adds every variable currently shown in the results to your basket in one click.
  • Download results (CSV) — exports just the rows currently matching your search and filters.
  • Download data dictionary — downloads the full NSHD Data Dictionary as an Excel file, independent of any filtering you've applied.

Longitudinal Search follows the same underlying pattern — live search, sortable columns, CSV export — but its controls are adapted to what it actually shows: a minimum sweep-count filter stands in for page size, and each row represents a whole Field ID rather than a single variable. Clicking View on a row expands it into a detail panel with a trajectory chart and a per-sweep statistics table, where you can add every sweep to your basket at once or pick individual ones — there's no separate "add all visible" button, since selection happens per Field ID inside the panel instead.

Search by Year departs further still: instead of a search box, a row of year pills is the primary filter, with topic filters layered alongside it rather than a text field. The two interact live, so you can see before clicking which years actually have relevant data for a given topic rather than finding out only after filtering. Once narrowed down to a set of years and topics, the underlying results still support the same add-to-basket and export actions as the other tools — just reached by clicking pills rather than typing.

Because the core pattern — filtering down to a result set, then adding to your basket or exporting — carries across all five tools, a workflow you build in one transfers easily to the others, even where the specific controls differ.

Explore documentation

Where the search-first tools return a table of variables, Topics, Questionnaires, and Documentation all return documentation — pages written to explain context, history, and measurement, rather than to list data fields directly. Use them when you want to understand a subject before (or instead of) searching for specific variables.

  • Topics — pages grouped by subject area (physical health, cognition, lifestyle, and so on), each explaining what was measured, how, and across which sweeps over the study's 80-year history. Most topic pages link out to the relevant questionnaires or variables rather than listing them on the page itself.
  • NSHD Questionnaires — the original survey instruments, organised sweep by sweep from 1946 onward. Each questionnaire is available as a downloadable PDF, with variable names annotated directly onto the document wherever possible, so you can see the exact wording behind any field.
  • Documentation — data notes, cleaning records, and other write-ups that explain how a variable or dataset was actually built, rather than what it measures. Where Topics and Questionnaires cover the study's design, Documentation covers its history — bug fixes, derivations, corrections. Each document is automatically checked against the data dictionary, so if it names real variables you'll see them listed on the page and can add them straight to your basket, the same as anywhere else on OWL.

None of the three are built around a search box or a results table the way Search Data Dictionary, Browse by Category, Popular Variables, or Longitudinal Search are — they're for reading and reference, with links onward to the data itself when you're ready to search for it.

If you're writing documentation rather than reading it, two tools cover that side specifically: Create Documentation Online builds a topsheet and its accompanying document directly in the browser, with a live preview of how it'll look once published, while Page Proof checks a document you've already written in Word for common formatting mistakes before you send it in. Both are linked from the Browse Documentation page.

The sidebar summary

Most pages across the OWL — including this one — carry a fixed sidebar summary on the right-hand side, listing every section on the current page as a clickable shortcut. It stays in view as you scroll, so on longer pages like Topics or Questionnaires you don't need to scroll back to the top to jump somewhere else.

  • On this page — a list of every major section, each linking straight down to it. Click any item to jump there immediately, no scrolling required.
  • Active section highlighting — as you scroll, the sidebar automatically highlights whichever section is currently in view, so you always know where you are on a long page.
  • Back link — most sidebars also include a link back to the parent page, useful for returning to a category or topic listing without using your browser's back button.

On narrower screens, the sidebar tucks itself away automatically to keep the page readable — a mobile-friendly back link appears in its place where needed. The same component appears with the same behaviour across Topics, Questionnaires, and most other documentation pages, so once you're familiar with it here, it works identically everywhere else.

Variable status icons

As you browse any table or documentation page, you'll sometimes see a small icon appear right next to a variable's name. These aren't tied to any particular tool — they're added automatically wherever a variable name appears, whether that's Search Data Dictionary, Browse by Category, Popular Variables, Search by Year, Longitudinal Search, or a Documentation page. Learn what they mean once, and you'll recognise them everywhere on the OWL.

  • Documentation available — this variable has one or more write-ups explaining how it was built: cleaning notes, derivations, corrections, or similar. Hover the icon to confirm, then click it to jump straight to the document. If more than one document covers the variable, clicking opens a short dropdown listing each one by type and title, so you can pick the right one rather than being sent to an arbitrary page.
  • Restricted variable — this variable has an additional access restriction beyond the standard public/sensitive classification. Hover the icon to see exactly why it's restricted and how to request it — the message is specific to that variable, for example naming who to contact or what a request needs to include. Unlike the documentation icon, there's nothing to click through to; the tooltip itself is the whole answer.

The two icons are independent, so it's entirely possible to see both next to the same variable — a restricted variable can also have documentation explaining it, and vice versa. Whenever a table or page has at least one icon showing, a short banner near the top explains what it means, as an on-page reminder if you land there without having read this page first.

The basket

The basket lets you collect variables as you find them — from search, category browsing, or questionnaire pages — into a single list you can review and export as a Excel file. Once you're ready, downloading your basket also builds you a fully-marked copy of the data dictionary — the spreadsheet NSHD needs for a formal data request — so the two are worth using together.

Sync linked sweeps. Some variables are collected identically — same question text and coding — across two or more sweeps (see Longitudinal Search above). A toggle next to the basket icon, visible on every page, syncs sweeps of the same longitudinal variable: turn it on and adding or removing one sweep automatically adds or removes its sibling sweeps in your basket too, so you don't have to track down and add each one individually. It's on by default; a brief confirmation names what changed each time, with the option to undo. Turn it off if you'd rather add sweeps one at a time.

Sync linked sweeps

You can also upload a basket — either a file you downloaded from OWL earlier, or a copy of the Data Dictionary you've marked up yourself with Y in the Request variable column. This is the easiest way to resume where you left off if you're switching computers, clearing your browser, or picking a project back up after a break, and it's also a quick way to add a large batch of variables in one go rather than one at a time. Before anything is added, you'll see a list of what's about to change so you can check it over first — including, if the toggle above is on, an option to bring in each linked variable's other sweeps at the same time.
