How the site is organised

Three core mechanisms make up the OWL: search-first tools, browse-first tools, and the variable basket.

On this page

  • Browse-first tools
  • The basket
Back to getting started

The OWL is built around three core mechanisms. Search-first tools work by keyword, for when you already have something to look for. Browse-first tools let you explore by subject or by sweep without a specific target in mind. The basket ties both together, letting you collect variables as you find them, from either approach, into a single exportable list.

Search-first tools

Two search tools sit at the front door of the OWL, and they're built for different jobs. The Data Dictionary Search reads at the level of individual variables — names, labels, descriptions, and the categories they belong to — so a query like "grip strength" or "BMI" surfaces the exact fields that match, narrowed further by the filter panel alongside it. The site search bar works one layer up: it indexes whole pages, scanning titles, headings, and body copy across the documentation. Reach for it when you're hunting a page rather than a variable — a questionnaire write-up, a topic explainer, a guidance note — and the Data Dictionary would otherwise return nothing because the thing you want isn't a variable at all. In short: variable-shaped questions go to the Data Dictionary, page-shaped questions go to the search bar.

Browse-first tools

Not every research question starts with a keyword. Topics and Questionnaires are built for that — two different ways of moving through the dataset without already knowing the name of what you need. Topics cuts across the whole 80-year study by subject: physical health, cognition, lifestyle, and so on, with each page explaining how a theme was measured over time. Questionnaires instead preserves the study's original timeline, sweep by sweep, so you can see precisely what was asked, of whom, and in what words at a given point in the study's history. Pick Topics when a theme is your anchor; pick Questionnaires when a year, age, or survey wave is. Both tend to function as a map rather than a destination — pointing toward relevant variables, categories, or instruments rather than listing every variable directly on the page itself.

The basket

Most research projects need more than one variable, and the basket is where that list gets built. Every variable metadata page carries an "add to basket" control, and the basket icon beside the site search bar keeps a running tally alongside a quick preview of whatever you've added most recently — handy for checking you grabbed the right field without leaving the page you're on. The basket page itself is where the real work happens: reorder, remove, double-check labels and sweeps, and export the whole selection as a CSV once it's ready. It's deliberately tool-agnostic — variables land in the same basket whether you found them through a keyword search, a category browse, or a questionnaire page, so it works as a single staging area regardless of which route through the OWL you took to get there.
